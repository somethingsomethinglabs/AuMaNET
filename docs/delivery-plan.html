Ownership and workflow

Rowan is the project owner and decides product scope, hardware changes and acceptance tradeoffs. Engineering roles below are accountability slots, currently unassigned unless explicitly noted; they are not commitments from other people. The maintainer taking a row records their name before starting and keeps its evidence current. Work budgets in the roundtable are experiment limits, not delivery dates.

States: queued, investigating, waiting for hardware, implemented (limited scope), verified (stated environment only), complete (all listed exit conditions), or deferred. Mark an experiment not run until executed; a missing device is not a failed test. Reopening an accepted result requires a new dated evidence entry. No production implementation is authorized merely by an experiment passing.

Existing prototype work

The UI and Android shell are implemented and have recorded browser/emulator verification (EV-UI). Mechanical reference and slice checks are recorded separately (EV-MECHANICAL, EV-PRINT). These complete those narrow prototype increments, not W03–W13. The earlier print-bundle overwrite blockage is historical; the later print verification records a successful canonical rebuild.

EV-DOCS records the current documentation verification. TypeScript, Svelte and handbook checks pass. The combined repository check currently fails in scripts/check-cad.mjs because the pre-existing custom model entries lack the upstream-only gitBlob field; W15 tracks that separate validator mismatch. This documentation change does not modify geometry, STL selection, the manifest or print-bundle tooling.
