## Current versus historical conflicts resolved

1. `design/phase-status.md` and many paragraphs of `design/android-app-plan.md`/`requirements-traceability.md` still describe an early sample-data app and unimplemented native/internet/maps work. They cannot be used as the current truth. Current native services and reachable components implement substantially more. The brief does not repeat the obsolete sample mode or old screen counts.
2. `design/software-requirements.md:24` still names the old Getlost/GeoTIFF map direction. Current `dev/app/README.md`, `MapPanel.svelte` and `GeographicMap.svelte` replace ordinary map use with vectors. `GeoTiffImport.svelte`, `GeoscienceDownload.svelte` and related storage/preparation code remain in the repository, but are not imported into the current `MapPanel`; therefore raster import/preparation is not a current normal-app requirement.
3. Earlier SW-19 shared-prefix/virtual-LAN intent was superseded in the software requirement header and SW-20/21 by routed node networks/multiple independently authorized phones. Current phone-facing maintenance is still notably two-node constrained. The neutral brief preserves the domain goal without inventing accepted broad topology support.
4. Historical voice plan and traceability tables understate current native voice implementation. Current controls/coordinators/preferences/Telecom support are present, but detailed audio, mixed-load and physical acceptance is still a different claim.
5. General board management and CLI requirements cover far more than the current app's concrete node actions. The neutral brief does not fabricate working app backup/reset/restore, generic reboot, arbitrary device rename, wireless first provisioning or admin transfer.
6. Some current code intentionally exposes legacy and engineering controls. These are covered under ENG as optional advanced simulation; they are not transmitted as normal navigation, test fixture selectors or old/new implementation toggles.

## Remaining uncertainty

- No app build/test run was requested for this read-only inventory, and no hardware was exercised. Presence of a contract test is not a passing result. The parent should validate its actual new implementation separately.
- The shared checkout is actively dirty. This inventory reflects what was present during inspection, including untracked app code. It is not a claim about any specific committed release.
- Current native/browser feature availability depends on registered plugins and device support. The clean-room prototype should model unsupported states without implementing those plugins.
- The app may contain less reachable methods in native controllers that are callable only by tests or external tooling. They were not promoted to user-facing requirements unless ordinary source or an explicit advanced surface uses them.
- Full firmware physical acceptance is governed by AGENTS.md: installed identity plus three fresh DHCP reconnects, reboot recovery, stable-address check and intended phone's per-SSID MAC through the actual Resume flow. This inventory neither performs nor claims that gate.
- Any real export, permission grant, message send, device change or firmware installation in the future prototype needs its own authorization context. This inventory authorizes only simulated behaviours for the blind design work.
