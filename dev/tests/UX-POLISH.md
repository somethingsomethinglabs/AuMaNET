# Overnight interface review

The selected demo remains the visual reference: warm paper, green controls, rounded cards and four main tabs. Before-change screenshots were captured and individually inspected before implementation under `output/playwright/ux-audit/before`. The preferred in-app browser was unavailable; the parent explicitly authorized a separate Playwright Chromium fixture. This never used the user's browser profile or operated a phone. Screenshots use synthetic native data. Parent-owned physical screenshots and acceptance are separate evidence.

| Step | Before | Implemented outcome |
| --- | --- | --- |
| Read messages | A per-message Details disclosure expands into long metadata, obscuring the conversation. | Time, concise delivery and available receiver-local signal appear inline. Optional signal is never inferred from a delivery receipt. |
| Open a photo | A small image has no normal full-screen open/save flow. | Tap opens a focused viewer with Enlarge/Fit, Close and explicit Save photo. Late reads cannot reopen a closed/changed conversation; object URLs are released. Native uncertain-save guidance asks the user to check Pictures/AuMaNET before trying again. |
| Find group members | Repeated connection/profile/name forms push actual members below the first viewport. | Groups & members opens members and invitation first. Personal and group-name editing are folded below the list. |
| Understand devices | Group phones, nodes and connections are mixed together. | Network shows Your phone → Your node → Other nodes. Other nodes opens the real observed node list and assigned phones; a phone and a radio node have separate details. No battery, firmware, hops or remote attachment is invented. |
| Tap map devices | A marker and its name open the same summary. | The marker opens the person/group summary. Its visible name opens exactly one checked assigned node, falling back to the phone when unmapped or ambiguous. Both actions have keyboard access and distinct accessible labels. |
| Understand radio | An unsupported reverse report can hide a usable measurement in the other direction. | Both endpoints show the available measured link, naming its counterpart and receiving node. Unknown/stale values remain honest. |
| Share internet | Controls do not reflect the native donor/consumer sessions. | Share my internet and Use shared internet are separate explicit choices. Limits are per session, eligible donors are selected manually, Android VPN consent is contextual, and exact Stop controls remain available after an observation error. |

`ux-polish-audit-capture.mjs` reproduces five after views at 390 × 844. `ux-polish-browser-verification.mjs` checks message/photo lifecycle, device identity, member ordering, map-name keyboard activation, light/dark narrow layouts and absence of hardware starts. `internet-sharing-browser-verification.mjs` checks the actual app and typed client with synthetic native states, including no-cell availability, separate roles, cancelled pending consent and late replies. These are registered in `web:test:ui`; the corresponding host cases run in `web:test`.

Opening or refreshing settings only reads snapshots. Internet start methods are called once per explicit gesture, uncertain replies are reconciled through reads without replay, and automatic donor switching is absent. The viewer's temporary dark system-bar hold does not save appearance settings. Host/browser checks do not establish Android VPN routing, notification permission, MediaStore completion, native Back behavior or physical radio performance; the parent records those against the exact installed APK.

The compact app header uses the same current group/self/epoch-scoped native Internet summary as Network. A donor's heartbeat deadline is not presented as the duration of a sharing session. Photo-preparation copy distinguishes removed embedded metadata from a separately attached shared-position record when location sharing is on.
