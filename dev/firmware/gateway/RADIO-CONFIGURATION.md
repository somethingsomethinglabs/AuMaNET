# Signed AU radio profile control, version 1

Only the physically checked current group owner may request this separate control purpose. It grants no clock, route, replay-floor, phone attachment or power authority. Current firmware catalog is the exact 23 IEEE802.11-2024 AU tuples in `radio_profile.c`; every entry is matched to the linked pinned SDK regulatory database before radio startup. Channels are operating channels, not phone Wi-Fi channels. Width is operating bandwidth; primary bandwidth remains the SDK-supported 1/2MHz selection. Configured TX ceiling is unchanged and is not measured RF output.

Both roles install this complete validated list. The station associates with the configured private WPA3 AP across that list and follows its operating channel; it cannot accept configuration mutations. AP changes use AP disable/enable without MCU reboot, trusted-time reset, key changes or phone AP changes. A trial must return to the old AP tuple after 30 seconds unless the owner commits after fresh authenticated readbacks from BOTH original node boots show the proposed actual tuple, with station associated. One explicit app Apply gesture may authorize a conditional signed commit after those checks. No timer-only/unattended commit, indefinite trial, replay extension or profile guessing is allowed. RF/hardware acceptance of this runtime SDK path is separate from host tests.

All integers are unsigned big endian. Framing is target-node16 + body + DER-length1 + strict P256 DER signature8..72, maximum321 bytes. CQ body136 magic `AUGWCQ1\0`; CR body232 `AUGWCR1\0`; CC body224 `AUGWCC1\0`. All share existing BOOT-style offsets: version1 at8, zero9..15, target16 at16, group16 at32, epoch8 at48, ownerSPKIpin32 at56, relayNode16 at88, fresh ownerChallenge32 at104. Different purpose domains prevent BOOT/TIME/grant reuse. There is a separate bounded lane and nonce/relay reservation; radio requests cannot replace BOOT/TIME or signal pending requests.

CR fields: nodeBoot16 at136; nodeNonce32 at152; transaction16 at184; configGeneration8 at200; currentOption1 at208; persistedOption1 at209; trialTarget1 at210; state1 at211 (0 idle,1 queued,2 applying,3 trial,4 reverting,5 failed,6 unsupported); trialRemainingMs4 at212; actualOption1 at216; associatedBool1 at217; roleStationBool1 at218; flags1 at219 (bit0 persistence known, bit1 AP mutation supported); lastError2 at220; catalogVersion2 at222 (=1); configuredTxCeilingDbm1 at224; zero225..231. Option0 means unavailable/unknown, never infer a default. The station has no persisted selection and reports persistedOption0. Its current/actual option comes from actual associated VIF information, not an inferred desired profile.

CC fields: expectedNodeBoot16 at136; nodeNonce32 at152; nonzero transaction16 at184; expectedConfigGeneration8 at200; operation1 at208 (1 trial,2 commit,3 cancel); targetOption1 at209; zero210..223. A fresh CQ creates a nonextendable 5-second node nonce. Exact duplicate CQ returns its cached signed report. CC consumes that nonce once; exact duplicates return a cached outcome without another operation or deadline extension. Every operation is checked against original boot, scope, challenge, nonce, generation and transaction. Fresh CQ retires the previous nonce. Mutations additionally require an initialized trusted clock and current physical field permission. Reports prove query/readback provenance, not packet RF freshness or exact radiated power.

Generation starts0 when no committed selection exists; only confirmed persistent commit+readback increments it. Trial/cancel/rollback/query do not increment it. Idle readback retains the last committed transaction for lost-reply reconciliation. A repeated commit for that exact transaction/current generation/current persisted target is idempotent. Unknown persistence outcomes are reported as failed/unconfirmed, never claimed as committed. Transient trials are RAM-only so reboot loads the last confirmed persistent record. A failed/unknown commit can have reached NVS despite an error: current-boot persistence is then unknown and RF rolls back in RAM; a reboot may read either old or new valid record. Fresh authenticated readback must reconcile it. Do not promise rollback across reboot after an unconfirmed persistent write.

A owner-side relay forwards B query/report only through the checked peer endpoint and original bounded challenge reservation. Source MAC/IP admission, signatures, target identity, and exact config/boot pinning stay in force. No app command can set arbitrary frequency, country, TX power, credentials, NVS keys or regulatory tables.

If a corrupt or unreadable new profile blocks RF startup, physically authorized USB recovery `gw-radio-default RUN` removes only `amn_radio1/profile`, confirms its absence, and requires a subsequent restart to use the compiled AU default. It refuses while the radio is started. It neither erases the NVS partition nor modifies keys, phone AP, acquisition, field permission or message history. An unconfirmed erase is reported as unavailable; it never claims successful recovery.
