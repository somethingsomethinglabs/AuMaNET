# Coordinated integration and acceptance checklist

Canonical runtime/native/UI/policy components have now been integrated into the application source with the coordinated 512 MiB limit. Parent owns final MainActivity registration/client hook, full builds and physical acceptance. The following checklist retains the implementation contract and remaining device checks; the old prototype/harness stays outside active src.

1. Pin `geotiff@3.0.5` and `@noble/hashes@2.4.0` in the app workspace and lockfile; retain `browser-preparation/THIRD-PARTY-NOTICES.txt` in the distributable notices. The isolated UPNG quality experiment is excluded. Bundle the dedicated worker/controller and pure helpers; preserve source size 256 MiB, 2 MiB range, 8 MP raster band, 8192 tiles and 512 KiB PNG bounds. Native output quota becomes deliberately 512 MiB, retaining full colour.
2. Extract/reuse one native manifest validator from existing `OfflineMapsPlugin.validate` for both prepared-pack import and generated maps. Raise its payload cap/message to 512 MiB and retain complete coverage/index/source/size validation. Validate native-generated manifest before activation; the worker's manifest/index is not accepted as authority. Stage/rename, selection and same-ID retirement must execute within one mutation lease.
3. Coordinate all other payload limits/messages: `dev/app/src/lib/maps/format.ts` (`MAX_PACK_BYTES`, validation message), `dev/maps/prepare-map.py`, `dev/maps/verify-overlap.py`, `browser-preparation/plan.mjs` payload only and OPFS worker budget message, plus map storage policy docs/UI. Source byte limits remain 256 MiB. Update cap tests with a bounded metadata fixture, not a new 512 MiB in-memory allocation. Four-region and existing replacement semantics remain.
4. Move/register only production classes `MapMutationLease`, `MapPreparationFiles`, `GeoTiffPreparationPlugin` into an agreed application package; the JVM test/harness classes stay outside active src. Parent owns MainActivity registration and shared build/manifest work. No new Android permission, NDK or Gradle library is needed: existing AndroidX WebKit 1.14.0 supplies the binary APIs. Runtime feature checks remain mandatory. Core uses minSdk24-compatible date/unsigned conversion methods.
5. Adopt **the same `MapMutationLease` class and canonical root** in existing prepared-pack import/removal and startup cleanup. Acquire prepared-pack mutation ownership before reading/writing a selected input and release in every error/cancel/success path. Removal owns a short lease. Reads/snapshot/render/focus selection remain usable. GeoTIFF source copy acquires a lease before copying and retains it through source-ready/preparation/finalization; failure/cancel/destroy/expiry release it. Both startup cleaners must coordinate so they cannot delete another component's active stage; consolidate startup cleanup or serialize/retry acquisition instead of treating a transient lease conflict as successful cleanup.
6. Use the native core's `finish(Activation)` callback to apply the shared validator, select the new instance and retire an old same-ID instance **before** releasing the global lease. Selection during preparation may remain available. A successful import focuses its newly verified region, matching current prepared-pack behavior. A late cancellation cannot delete a committed instance. A failed selection/retirement must preserve a usable verified region and surface an honest recoverable state.
7. Add one normal user Maps import entry that accepts a prepared pack or supported GeoTIFF. For TIFF, `chooseSource()` invokes SAF and returns native sourceId/fileName/bytes/hash/path. `NativePreparationController.run(source,{id,title,source},onProgress)` drives the worker and binary bridge; `cancel()` closes pending work and native staging. Supply actual source name/link/attribution/licence/original data date and show preparation changes/storage requirement. No fake fixtures, developer switches, online fallback or silent colour fallback. Supported-file/low-space/unsupported-format/cancel states belong in this ordinary import flow.
8. Run focused host contracts, coordinated format/import regressions, Svelte check and parent-owned Android build. Physical acceptance then uses real source on both phones: actual `https://localhost` main frame, native206 file range headers/body bounds, binary feature support, 256px PNG decode, atomic ready activation/replacement, retained old region on unsupported/low-space/cancel failure, process death/worker termination cleanup, reload/offline tile rendering and visible attribution. Decoder timing/memory/persistence on desktop are not phone acceptance. Parent controls phone/build operations.

Binary frame and metadata/API contract, exact provenance/measurements and open acceptance limits are in `../browser-preparation/README.md`. Tests:

```powershell
node --test dev/maps/browser-preparation/*.test.mjs
node dev/maps/android-prototype/test-map-preparation.mjs
```

The optional `MapPreparationHttpHarness.java` is a local-only desktop integration fixture for the earlier staged path. It uses an explicit private raw source argument, loopback port and ignored output directory, JVM ImageIO instead of Android BitmapFactory and an HTTP test bridge instead of AndroidX. Never register or bundle it as application code.
