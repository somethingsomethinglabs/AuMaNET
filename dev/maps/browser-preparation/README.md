# GeoTIFF preparation design and historical prototype evidence

The active implementation is now `dev/app/src/lib/maps/preparation/` plus `dev/mobile/android/app/src/main/java/au/aumanet/app/maps/`, with a coordinated 512 MiB payload policy and normal GeoTIFF import UI. It uses an app-owned query-read/PNG endpoint rather than the SDK file server. Full build and actual-phone acceptance remain parent-run gates. The following sections retain the earlier prototype design/measurements; statements about staging or the former 256 MiB policy describe that historical checkpoint. They are not the current product integration status.

Current storage/flow/verification details are in `../README.md`. The original prototype source remains outside the app bundle for reproducibility.

The implementation uses maintained **geotiff 3.0.5** for TIFF/JPEG decoding and **@noble/hashes 2.4.0** for incremental source/tile SHA-256. It does not implement a TIFF codec or require an NDK/SDK download. Dependencies currently live only in the ignored isolated prototype installation. The root lockfile is untouched. `THIRD-PARTY-NOTICES.txt` includes the selected dependency graph's licence texts, including the decoder's embedded JPEG licence. A separately evaluated old UPNG quantizer is **not** selected or imported by this source.

Supported input is deliberately narrow: classic stripped TIFF, unsigned interleaved RGB8, normal orientation, north-up EPSG:3857 pixel-area coordinates, uncompressed or JPEG strips, no nodata mask. Tiled TIFF/BigTIFF/other CRSs/other encodings fail explicitly. Tiled JPEG is excluded in part because the upstream decoder tracks an unpadded-edge JPEG issue. Source ≤256 MiB, dimensions ≤16384×32768, strips ≤64 rows, source reads ≤2 MiB, raster band ≤8 million pixels, ≤8192 XYZ tiles, PNG ≤512 KiB, and metadata ≤2 MiB. Unsupported formats need a later reviewed decoder/policy expansion.

`worker.mjs` is the verified OPFS prototype: it reads the source in bounded ranges, decodes full-width strip-row bands once, samples native-grid XYZ tiles, and derives lower zoom levels from four local child PNGs. It emits full-colour PNG by default. Its existing 256 MiB output limit deliberately rejects the full-colour Moe result; the ignored measurement run used a private benchmark cap override. Experimental `rgb444` is explicit and records its transformation; it is not a fallback or recommended product default. A single lifecycle `try/finally` removes failed/cancelled output and closes the decoder. A Web Lock prevents competing cleanup, and the next operation removes interrupted stages while retaining completed ones.

## Actual source measurements

The public publisher source is `8121-8221_MOE-TRARALGON_GetlostMap_V16b.tif`, 116,697,376 bytes, source SHA-256 `f43682732386f8e0f6c0c01a7a4959a032f2100142671cd184882479248feb49`. Getlost's current information lists CC BY-NC-ND 4.0; private non-commercial preparation is the chosen use. Source and generated rasters remain ignored/private; no redistribution is selected. Attribution, original data date, original source hash and preparation transformations stay in the manifest. No personal phone coordinates are used in these measurements.

Desktop Chromium full-colour preparation produced 3,138 tiles (zooms 10–14), **440,032,030 payload bytes / 419.65 MiB**, in 64.45 s. Max compressed source read was 214,616 bytes; max decoded raster band 11,086,497 bytes; largest PNG 203,943 bytes; UI heartbeat max gap 65.1 ms. These are measured values on this workstation, not phone timing or a proven peak process-memory bound. Earlier RGB444 used 244,125,476 bytes but visibly posterized shading. Three actual highest-zoom full-colour worker PNGs at public Moe, Traralgon and Yallourn North landmarks matched every RGBA channel of the unquantized decoder/resampler output (max difference zero). The original JPEG decoder differs slightly from GDAL at some channels (measured maximum one on a full-width reference band), which is a decoder difference rather than colour quantization.

Parent-approved **design target**: a deliberate 512 MiB payload quota so this source retains full colour. Activation requires one coordinated review/change of browser format/store, native pack validator, preparer/native pipeline and user-visible storage policy. Existing ready regions and the stable native source copy must fit alongside the new stage. Native checks available storage before beginning and during writes; old ready data survives preparation failures. At begin it reserves payload plus 8 MiB and two filesystem allocation units per planned tile for directory/file slack; the Android adapter supplies `StatFs.getBlockSizeLong()`. Each write rechecks space including allocation overhead. The active limit has not been increased by this prototype.

Ignored evidence: `dev/artifacts/maps/geotiff-worker-lossless-result.json`, `geotiff-prototype/lossless-quality-results.json`, `geotiff-node-audit.json`, `geotiff-dependency-audit.json`, and `geotiff-dependencies.json`. Preserve the older failed/quantized measurements as separate evidence.

The staged **native raster worker/controller** was also run end-to-end with the actual source through a local desktop JVM sink fixture (`MapPreparationHttpHarness.java`): strict 206 reads, sequential strip/JPEG preflight, transferred PNG ArrayBuffers, the actual native staging core, per-tile SHA/PNG decode/fsync, native source rehash/index generation and atomic commit. It completed all 3,138 tiles in 143.78 s with a 66 ms maximum main-thread heartbeat gap. Every resulting PNG hash/length matched the previous full-colour OPFS run; payload remained exactly 440,032,030 bytes and the three public landmark RGBA comparisons remained exact. Source and incomplete stage were removed. A second real-source run cancelled after 16 native tile writes, rejected the caller's pending run promise, removed its source/stage and preserved the previous ready manifest. Evidence: `geotiff-native-worker-result.json`, `geotiff-native-worker-validation.json`, `geotiff-native-worker-cancel-result.json` under ignored artifacts. The local fixture uses JVM ImageIO instead of BitmapFactory and a test fetch rewrite/HTTP binary endpoint instead of AndroidX; these results do **not** establish actual phone WebView/SAF/binary-listener acceptance. Both owned fixture servers/browser were stopped; completed browser-only benchmark staging was removed after retaining metadata, sample images and the identical native output.

## Native binary contract under review

`../android-prototype/MapPreparationFiles.java` is a platform-independent native staging core. `GeoTiffPreparationPlugin.java` is an Android adapter scaffold, independently compiled against the project's existing Android 36, Capacitor and AndroidX WebKit 1.14.0 jars. Neither is in active Android source or registered. `native-transport.mjs` implements the matching binary sender; `range-client.mjs` implements the maintained decoder's `fromCustomClient` interface for strict local reads. `native-controller.mjs` and `native-raster-worker.mjs` wire the main-frame binary sender to a dedicated raster worker. `decode-policy.mjs` decodes one TIFF strip at a time and checks baseline JPEG frame dimensions/sampling before the maintained decoder can allocate pixels; this is header preflight, not a TIFF/JPEG pixel codec.

The planned flow is ordinary Maps import: SAF chooses a TIFF; native copies it using a 64 KiB buffer into a token-owned app-private source file and computes its checksum; the worker reads bounded binary ranges from that stable local copy. Native `begin` receives only small source attribution/geometry metadata, derives the allowed XYZ index itself, and creates a token-owned stage. The worker posts one encoded tile to the main frame, which awaits its native write acknowledgement before accepting another. Lower zoom generation reads one prepared child PNG at a time from native-owned paths. `finish` rechecks the native source hash, constructs the manifest from native-owned source/index/accounting, writes it last and atomically renames the stage into a ready instance. Worker paths and worker manifests are never accepted as write authority.

The injected binary object is `window.AuMaNETMapPreparationFiles`. AndroidX listener allowlist is exactly `https://localhost`; callbacks additionally require the HTTPS localhost origin/default port and main frame. External live-reload URLs, other schemes/origins/ports and child frames are rejected. WebView must support `WEB_MESSAGE_LISTENER` and `WEB_MESSAGE_ARRAY_BUFFER`; no base64/string fallback. These requirements follow the [AndroidX listener documentation](https://developer.android.com/reference/androidx/webkit/WebViewCompat#addWebMessageListener(android.webkit.WebView,java.lang.String,java.util.Set,androidx.webkit.WebViewCompat.WebMessageListener)) and [ArrayBuffer message API](https://developer.android.com/reference/androidx/webkit/WebMessageCompat).

All multi-byte integers use big endian. A write is one `ArrayBuffer` with this 76-byte header followed by raw PNG bytes:

| Offset | Type | Value |
| --- | --- | --- |
| 0 | 4 bytes | ASCII `AMPT` |
| 4 | uint8 | version 1 |
| 5 | uint8 | operation 1: PNG tile |
| 6 | uint16 | header size 76 |
| 8 | 16 bytes | random native generation/session token |
| 24 | uint32 | exact next sequence, starts at 0 |
| 28 | uint8 | XYZ zoom |
| 29 | 3 bytes | reserved, all zero |
| 32 | uint32 | tile X |
| 36 | uint32 | tile Y |
| 40 | uint32 | exact payload size, ≤512 KiB |
| 44 | 32 bytes | SHA-256 of PNG payload |
| 76 | bytes | PNG payload |

Native validates frame/token/sequence/geometry/duplicate/quota, PNG signature/IHDR dimensions and hash **before** bounded image decoding. A gate admits at most one binary task to the executor; 1,000 additional offers were rejected without queue growth. Every successful acknowledgement follows flush/fsync and contains only `schema: aumanet.map-preparation-ack.v1`, sessionId, sequence, ok, storedBytes and totalBytes. Failures include a short error. A stale-generation frame cannot cancel the current preparation. JS matches generation and sequence, rejects concurrent writes, and closes on invalid accounting/native failure/timeout. There is no retransmission protocol; a lost acknowledgement cancels/restarts the preparation rather than guessing whether a tile committed.

Cancellation/expiry removes the source and incomplete stage. Native has a 15-minute monotonic session deadline and adapter timeout; process-death or worker termination is cleaned on next startup. Completed regions survive late cancel. Finalization and cancellation serialize so a late cancel cannot remove a committed directory.

`MapMutationLease.java` provides a process-wide, canonical-root lease. The staged preparer holds it from native source-copy start through activation/cancellation, including the idle source-ready phase. Begin/copy/finalization failures release it. An activation callback lets integration select the verified instance and retire an older same-ID instance before releasing the lease. Orphan cleanup takes the same lease briefly. Existing pack import/removal still need to adopt this **same** class before activation; simply giving each plugin its own busy flag is insufficient. Listing/rendering/reads remain available. Ordinary map selection may continue during preparation; successful import focuses the newly verified region, matching existing prepared-pack import behavior.

`LocalRangeClient` pins the source URL to the internal `https://localhost/_capacitor_file_/` path, requires an exact 206 Content-Range and known native source size, clamps only bounded EOF metadata reads, and limits streamed response bytes before allocating more than the requested range. Full-file, shifted, overlong and truncated replies are rejected. The [maintained decoder remote-source implementation](https://github.com/geotiffjs/geotiff.js/blob/v3.0.5/src/source/remote.js) supports a custom client with full-file fallback disabled. Actual compressed-strip offsets/counts are independently checked against source size before decoding.

## Review and remaining integration

This checkpoint supplies the decoder/OPFS pipeline plus staged native storage, binary client, strict range client, controller/raster-worker wiring, global mutation lease and Android listener scaffold. It does **not** register/bundle these components, add a product import UI, adopt the global lease in the existing pack importer, unify all format limits, select/retire same-ID native regions, or establish physical WebView 206/binary/decode/low-storage/cancel/process-death acceptance. The adapter intentionally returns a committed instance to integration code rather than silently selecting it under the old 256 MiB validator. No integrated online catalogue or resumable download is claimed.

Before activating, share one map-mutation lock across prepared-pack import/removal and GeoTIFF preparation/finalization, use the reviewed shared validator/512 MiB policy everywhere, connect the maintained decoder worker to the native sink, provide normal user import/progress/cancel/error controls, and test both actual phones with the real Moe source while preserving old regions. Product development diagnostics do not belong on the main Map surface.

```powershell
node --test dev/maps/browser-preparation/*.test.mjs
node dev/maps/android-prototype/test-map-preparation.mjs
```

Fifteen JS contracts cover unsupported metadata, footprint/grid/sampling, exact binary framing, acknowledgement/backpressure/cancellation/timeout, local URL/range/EOF policy, malformed responses, bounded JPEG-frame/shared-table metadata, sequential strip decoding and worker-creation failure cleanup. Eleven independent JVM scenarios cover source copy/hash/cancel, origins, native plan bounds, JS-generated frame→real PNG decode/atomic commit, a flood, generation isolation, corrupted frames before decode, quota/decode/filesystem failures, prior-ready preservation, orphan cleanup, source mutation, four-region/replacement and global lease lifetime/release rules. JVM ImageIO substitutes for Android BitmapFactory only in tests; the unregistered adapter uses BitmapFactory after frame validation. Five actual-source desktop browser lifecycle checks cover quota/canvas failures without a stage, cancellation cleanup, termination and next-attempt orphan cleanup while preserving completed output; evidence is `dev/artifacts/maps/geotiff-worker-lifecycle-result.json`. Additional preflight checks accept all 643 actual compressed strips and the 73-byte shared JPEG table while rejecting hidden extra/oversized image frames; `geotiff-all-strip-preflight-result.json` records this separate post-run hardening check without claiming another pixel-decoding benchmark.
